# Codebase Concerns

**Analysis Date:** 2026-08-17

> Judgment context: this repo is explicitly **pre-release** ("foundation over blast radius", per `AGENTS.md`). No compatibility shims, backends reject old on-disk formats, SQLite `SCHEMA_VERSION` monotonic, `SESSION_FORMAT_VERSION` at `0`. Several "concerns" below are deliberate pre-release trade-offs rather than defects; these are flagged so a plan does not reintroduce them silently. The single largest, genuinely actionable security gap is the SSRF primitive in the web provider (explicitly deferred) and the fail-open settings redactor.

## Tech Debt

**Vendored Cordis divergence:**
- Issue: `vendor/` holds pinned copies of the entire Cordis framework (core, loader, include, group, timer, hmr, logger-console, schemastery, cosmokit). `vendor/README.md` documents **18 separate local modifications**, several of which are non-trivial lifecycle hardening, transactional reconciliation, and deadlock fixes (`cordis/src/fiber.ts`, `include/src/index.ts`, `hmr/src/index.ts`). The Cordis core and loader are pinned to fork repos (`github.com/deepseek-harness/cordis`, `deepseek-harness/cosmokit`, `deepseek-harness/schemastery`) at SHAs, not the upstream `cordiverse/cordis`.
- Impact: any upstream security or correctness fix requires manual re-sync plus re-applying 18 patches; the fork repos add a supply-chain surface (a compromised fork SHAs into the harness). Divergence from upstream Cordis means `@deepseek-ai/cordis` behaves differently from `cordis` consumers expect.
- Fix approach: keep the exhaustive modification log (already required by `vendor/README.md`); before the first tagged release, upstream the still-open fixes (e.g. the fiber reentrancy gaps, `cordiverse/cordis#41` lazy-config) so future syncs shrink. The `verify-vendored-links` hygiene gate already asserts no registry copy sidesteps the pin.

**Large hand-written files (complexity hotspots):**
- `packages/host/apiproxy/src/api-proxy.ts` — 3744 lines, the single largest hand-maintained file; a monolithic JSON-RPC gateway touching sessions, workspaces, subagents, presets, projections, search, and credentials.
- `packages/client/connection/src/client/fixture.ts` — 3188 lines, a standalone UI-development fixture server with a 74-turn hand-built script.
- `packages/typert/generator/src/analyzer.ts` — 3113 lines, the TypeScript AST/symbol analyzer.
- `packages/typert/generator/src/cordis-catalog.ts` — 1059 lines, Cordis-specific catalog projection.
- `packages/core/tools/src/index.ts` — 1946 lines, the scoped tool registry and guarded execution pipeline.
- Impact: these are where a single change touches many subsystems; `api-proxy.ts` especially is both the largest file and the one carrying the redaction XXX (below), so edits there are high-risk.
- Fix approach: `api-proxy.ts` should be decomposed per domain (the `api/` sibling dir already splits view helpers — extend that). Do not treat the generated `api-catalog.ts` (4816 lines, `tool-cordis/src/api-catalog.ts`) or `slot-catalog.ts` (1722 lines) as hand code; they are regenerated by `gen-cordis-api.ts` / `gen-client-catalog.ts` and must not be hand-edited.

**Patch-managed native dependency:**
- Issue: `patches/node-pty@1.1.0.patch` patches `node-pty` directly (pnpm `patchedDependencies`).
- Impact: a `node-pty` upgrade or patch-application regression breaks `spawnTerminal` (`packages/terminal/*`, `packages/subprocess/subprocess-local/src/terminal.ts`); patch conflicts are a recurring upgrade hazard.
- Fix approach: track the patch's purpose and re-verify on every `node-pty` bump; consider upstreaming the patch.

**Build artifacts committed in the workspace tree:**
- Issue: compiled `.js`/`.map`/`.tsbuildinfo` outputs are present inside `packages/*/*/lib/` and `vendor/` per the directory listing (`lib/` dirs, `tsconfig.host.tsbuildinfo`, `tsconfig.client.tsbuildinfo` at root).
- Impact: risk of editing built output instead of `src/` (stale `lib/` misleads tools that read artifacts), and noise for `grep`/duplication scans.
- Fix approach: confirm `.gitignore` covers `lib/`, `*.tsbuildinfo`; keep `pnpm run clean` (`scripts/clean.ts`) the authoritative removal path.

## Known Bugs

**E2B rollback swallows double-failure:**
- Symptoms: on sandbox setup failure (`packages/e2b/e2b/src/index.ts` `open()`), the kill-rollback `catch` is an empty swallow with a TODO; a real double failure (setup + rollback both fail) leaves no diagnostic and no retry.
- Files: `packages/e2b/e2b/src/index.ts:170-177`
- Trigger: E2B sandbox creation or the chmod/mkdir setup failing while `sandbox.kill()` also fails.
- Workaround: none (the original setup error is still thrown); severity low because E2B is a POC group.

**Settings redaction returns secrets verbatim (fail-open):**
- Symptoms: `redactSecrets()` (`packages/settings/settings/src/redact.ts`) walks only `object`/`dict`/`array` containers. A secret reachable only through a **union, intersection, or transform** hits the `default` branch and is returned verbatim, with nothing recording the miss.
- Files: `packages/settings/settings/src/redact.ts:86-90`
- Trigger: any settings schema field marked `role('secret')` modeled via a union/intersection/transform; the value then crosses a wire boundary (settings view/host API) unredacted.
- Workaround: none — the codebase's own JSDoc requires "a secret buried inside a union branch or transform … must not be modeled that way", but nothing enforces it. This is a latent secret-leak defect the moment such a field exists. Fix is the `TODO(settings-wire-redaction)`: fail closed instead.

## Security Considerations

**SSRF primitive in the web provider (highest priority):**
- Risk: `packages/web/web-fetch-http` performs arbitrary public HTTP(S) fetches on model-invoked URLs and explicitly defers **all** private-network protection — no blocking of private/loopback/link-local/multicast destinations, no DNS-resolve-then-validate, no per-hop re-validation. The README states this provider "is an SSRF primitive and **must not be enabled** in a deployment that can reach sensitive internal network targets."
- Files: `packages/web/web-fetch-http/README.md` (Known Limitations), provider in `packages/web/web-fetch-http/src/`
- Current mitigation: only transport hygiene (scheme allowlist, no URL credentials, redirect hop cap, same-origin redirects, byte/char caps, timeout). None of these stop SSRF.
- Recommendations: before the first tagged release, ship the deferred SSRF protection (private-range blocking, DNS re-validation) or gate the provider behind an explicit non-default enable flag that composition bundles do not turn on. This is the single most important security fix outstanding.

**ApiProxy exposes unredacted provider details:**
- Risk: `packages/host/apiproxy/src/api-proxy.ts:2157` — error messages surface `String(error)` from session search and other providers. The codebase's own `XXX` notes this must be redacted before the gateway is exposed beyond its current single-user local deployment.
- Files: `packages/host/apiproxy/src/api-proxy.ts` (search/error paths)
- Current mitigation: the gateway is currently treated as local single-user only.
- Recommendations: normalize/redact provider error messages into the documented error taxonomy before any network-multiuser exposure; track the existing `XXX`.

**Settings redaction fail-open (see Known Bugs):**
- Risk: schema-declared `role('secret')` values can cross wire boundaries unredacted through union/intersection/transform models.
- Files: `packages/settings/settings/src/redact.ts`
- Recommendations: implement the `TODO(settings-wire-redaction)` fail-closed path; add a verification gate that rejects any `role('secret')` field modeled through a non-`object`/`dict`/`array` container.

**Credential scrub is a name heuristic:**
- Risk: `packages/subprocess/subprocess-local` scrubs spawned-command env only for names matching `*KEY*`/`*PASSWORD*`/`*SECRET*`/`*TOKEN*` (and all `DSH_*`). Differently-named secrets (`*PASSPHRASE*`, `*PASSWD*`, `*API*TOKEN*` variants already covered but e.g. `*AUTH*`) pass through into child processes, their `env`, output, and spill files.
- Files: `packages/subprocess/subprocess-local/README.md` (Known Limitations); implementation in `packages/subprocess/subprocess-local/src/spawn.ts`
- Current mitigation: only the name heuristic; the README names a whitelist for over-scrubbed vars as "noted future work".
- Recommendations: broaden the deny-list (add `*PASSPHRASE*`, `*AUTH*`, `*PASSWD*`, `*PWD*`), and prefer an allow-list of known ambient vars plus explicit merge, rather than a deny-list.

**Windows sandbox is only partial enforcement:**
- Risk: `packages/sandbox/sandbox-local` reports `windows-acl` as `partial` because `WRITE_RESTRICTED` must retain Everyone in the restricting list and NTFS hard links can alias a granted workspace file to a path outside it.
- Files: `packages/sandbox/sandbox-local/src/index.ts` (`STATIC_ENFORCEMENT`)
- Current mitigation: the backend fails closed on unavailable runners and self-reports partial; consumers see the enforcement claim.
- Recommendations: treat the `partial` claim as authoritative in any security-relevant composition and document that Windows confinement is weaker than Linux/macOS.

**Session telemetry ships raw captured content with no redaction rules:**
- Risk: `packages/session/session-telemetry-otel` uploads the complete `event.data` (user/assistant messages, tool args/results incl. command output and file contents, full system prompt and tool schemas, todo text, compaction summaries, hook stderr, feedback, session `cwd` local path). With no `sessionTelemetry/record` listener mounted, the uploaded copy is raw.
- Files: `packages/session/session-telemetry-otel/README.md`; seam in `packages/session/session-telemetry/`
- Current mitigation: adapter API keys are structurally absent (constructor params, not session events), so provider credentials never appear. Deployment must mount its own redaction rules to protect everything else.
- Recommendations: default the `FULL` mode to mount a conservative redaction rule set, or require an explicit opt-in to ship raw content beyond a trusted boundary.

**Untrusted-input surfaces are mostly validated, but composition can bypass:**
- Risk: JSON-RPC server (`packages/sdk/`) and ACP server (`packages/acp/`) accept wire input; `cordis.yml` allows `!!js` (never `!js`) under plugin `config` and entry `disabled`. `AGENTS.md` explicitly trusts typed same-process boundaries and validates at parser/config, queued, model/tool JSON, durable/file, worker, process, and wire boundaries — so an unvalidated JSON-RPC method or an ACP request is a real attack surface.
- Files: `packages/sdk/`, `packages/acp/`
- Current mitigation: per-`AGENTS.md` validation policy plus `verify-cordis-config` enforcement; the `!!js`/`!js` distinction prevents arbitrary JS in metadata.
- Recommendations: confirm the JSON-RPC and ACP servers validate against schemas (not trust caller-supplied `any`) and are not reachable by default in a network-multiuser deployment.

**Credentials document is well-guarded (positive note):**
- The `credentials-local` provider rejects a world/group-readable `$DSH_HOME/.credentials.yaml` before reading it (`assertOwnerOnly`), writes at `0600`/`0700`, never prints secret values (only codes/positions), and unshadows writes. The only gap is Windows (no mode enforcement, documented). `.env` files exist at repo root and are read as fallback layers; the environment layer is read-only and wins. **Never quote `.env`/`.credentials.yaml` contents.**

## Performance Bottlenecks

**Session logs accumulate with no deletion/retention API:**
- Problem: "Nothing deletes stored sessions" — rows/artifacts accumulate until removed externally; the seam has no deletion API (`ON DELETE CASCADE` is wired only for out-of-band cleanup).
- Files: `packages/session/session-persistence/README.md` (Known Limitations); backends `packages/session/session-persistence-jsonl/src/index.ts`, `packages/session/session-persistence-sqlite/src/index.ts`
- Cause: append-only event-sourced log is the single source of truth; compaction rewrites *surface* but never truncates the durable log.
- Improvement path: add a retention/deletion API to `SessionPersistence` before release; compaction must not grow the log unboundedly.

**Spill files accumulate in OS tmpdir:**
- Problem: completed spill files and the private per-process spill dir are not deleted; they accumulate under the OS tmpdir until something external cleans them (an oversize incomplete spill is discarded, but a bounded full-output file remains).
- Files: `packages/subprocess/subprocess-local/README.md` (Known Limitations); `packages/subprocess/subprocess-local/src/spawn.ts`
- Cause: bounded full-output recovery files intentionally outlive the read; no TTL.
- Improvement path: add temp retention/cleanup policy.

**`list()` is unpaginated and unfiltered:**
- Problem: `ctx.sessionPersistence.list()` returns every stored session header; fine for local stores, unindexed at scale.
- Files: `packages/session/session-persistence/README.md` (Known Limitations)
- Improvement path: page/filter the listing before large deployments.

**Type graph generation (Typert) is the heaviest build step:**
- Problem: `packages/typert/generator/src/analyzer.ts` (3113 lines) runs a full TypeScript program walk per face to produce the compiler-independent model and generated catalogs; `gen-cordis-api`, `gen-client-catalog`, `gen-tool-catalog` regenerate large artifacts.
- Files: `packages/typert/generator/src/analyzer.ts`, `cordis-catalog.ts`, `emitter.ts`
- Improvement path: the analyzer already caches (`WorkspaceCaches`); incremental/face-scoped runs should be preferred over whole-repo regeneration in dev loops.

**Large workspace builds:**
- Problem: `~3300` TS files across 38+ packages; `typecheck`/`lint` require a full `build:lib:host` first (contracts-ready gating). Every typecheck/lint run pays a full `tsc -b`.
- Files: root `package.json` (`typecheck`, `lint`, `build:lib:host`)
- Improvement path: rely on `tsc -b` incremental project references (`.tsbuildinfo` present) so rebuilds are partial; avoid forcing a clean build in local dev.

## Fragile Areas

**Vendored Cordis lifecycle code (see Tech Debt):**
- Files: `vendor/cordis/src/fiber.ts`, `vendor/loader/src/index.ts`, `vendor/include/src/index.ts`, `vendor/hmr/src/index.ts`
- Why fragile: the local modifications include reentrant-disposal hardening, transactional reconciliation, and deadlock fixes — precisely the classes of bug that regress silently on sync or refactor.
- Safe modification: only through the `vendor/README.md` sync procedure with the modification log; never hand-edit a vendored file without adding a log entry. `verify-vendored-links` gate covers resolution, not behavior.
- Test coverage: covered by `packages/boot/app-boot/tests/{app-boot,config-reload,user-patches,hmr-config}.spec.ts` and `apps/cli/tests/*.e2e.ts`.

**Cross-package capability seams (high coupling at the boundary):**
- Files: `packages/core/tools/src/index.ts` (1946 lines), `packages/subprocess/subprocess-local/src/spawn.ts`, `packages/shell/bash-local/src/index.ts`
- Why fragile: a capability seam spans Service Definition / Provider / Consumer in separate packages; the providers are swapped by composition, so a change to one seam role (e.g. subprocess disposal, bash timeout classification, tool `tools/execute` guard) ripples across consumers. `AGENTS.md` warns that "changing `agent-loop` requires updating docs/architecture.md".
- Safe modification: follow the "registrations are effects" and "waterfall listeners MUST call `next()`" rules; touch one seam role at a time and keep the three-role completeness invariant.
- Test coverage: seam behavior covered across `packages/{shell,subprocess,terminal,guard,tools}` unit tests plus `apps/cli/tests/*.e2e.ts`.

**Session persistence write coordinator:**
- Files: `packages/session/session-persistence/src/coordinator.ts` (1361 lines), backends `jsonl`/`sqlite`
- Why fragile: batching windows, crash-tail repair, live-adoption, and bounded flush state interact; torn-tail truncation and synthetic closers are crash-time behavior that is hard to reproduce.
- Safe modification: keep the `PersistenceBackend` hook contract and the write-coordinator invariants (append-only, contiguous seq, durable return) intact.
- Test coverage: backend unit suites plus crash-repair fixtures in `packages/session/session-persistence*/tests`.

## Scaling Limits

**Durable session log growth (see Performance):**
- Current capacity: unbounded append-only log per session; `list()` unpaginated.
- Limit: disk growth over long-lived or many sessions; no retention policy.
- Scaling path: add retention/deletion to the seam before release.

**Windows process-tree / terminal confinement:**
- Current capacity: `taskkill /T /F` best-effort tree termination; terminal inspection Linux/macOS only; Windows sandbox partial.
- Limit: daemonized/reparented descendants and `setsid` children can escape; macOS reparenting and Linux `setsid` escape the observable boundary (documented).
- Scaling path: a continuous process-table monitor (currently absent by design).

## Dependencies at Risk

**Vendored Cordis fork repos (highest supply-chain risk):**
- Risk: `@deepseek-ai/cordis`, `@deepseek-ai/cordis-plugin-loader` etc. are pinned to SHAs in `github.com/deepseek-harness/cordis` forks plus `deepseek-harness/cosmokit` and `deepseek-harness/schemastery` forks. If a fork is compromised or abandoned, the harness inherits it; divergence from upstream `cordiverse/cordis` grows.
- Impact: security, correctness, and upgrade path all depend on maintaining the forks and the 18-modification log.
- Migration plan: keep the modification log exhaustive; upstream the open fixes; re-verify `rescope-vendor:check` and `verify-vendored-links` after any sync.

**`node-addon` Landlock native build:**
- Risk: `native/landlock-run` builds a native addon with per-arch artifacts, consumed by `@deepseek-ai/node-addon-landlock-run`. Build complexity spans three npm packages with platform optional deps.
- Files: `native/landlock-run/`; consumed in `packages/sandbox/sandbox-local/src/index.ts`
- Impact: a Landlock ABI change or build-platform gap makes the Linux sandbox unavailable (fails closed, so confinement degrades to "unavailable" rather than unsafe — acceptable, but a feature regression).
- Migration plan: the `Landlock Run` CI workflow already builds/tests each arch; keep the release procedure in `native/landlock-run/docs/release.md`.

**`node-pty` patch:**
- Risk: `patches/node-pty@1.1.0.patch` is patch-managed; a bump or patch rejection breaks terminal sessions.
- Files: `patches/node-pty@1.1.0.patch`, `packages/terminal/`, `packages/subprocess/subprocess-local/src/terminal.ts`
- Impact: `spawnTerminal` (persistent PTY) stops working.
- Migration plan: verify the patch on every `node-pty` bump; upstream if possible.

**LLM API dependency:**
- Risk: `packages/llm/llm-deepseek` and `packages/llm/llm-pi-ai` depend on remote LLM APIs. `llm-pi-ai`'s SDK flattens the Error `cause` chain, forcing text-pattern classification (`stream.ts:31` `XXX(pi-ai upstream)`).
- Files: `packages/llm/llm-deepseek/src/adapter.ts`, `packages/llm/llm-pi-ai/src/stream.ts`
- Impact: provider wording/API changes can break error classification (`CONTEXT_WINDOW_EXCEEDED` normalization is adapter-maintained per `compaction-basic` README).
- Migration plan: keep overflow/error classification normalized inside the adapters; prefer `code`/`cause` over text when the SDK forwards them.

## Missing Critical Features

**SSRF / private-network protection (deferred):**
- Problem: the web fetch provider is an SSRF primitive; private-range blocking and DNS re-validation are named deferred work.
- Blocks: safe network-multiuser or sensitive-network deployments of the web capability.
- Priority: High.

**Settings secret redaction fail-closed:**
- Problem: the redactor returns union/intersection/transform-modeled secrets verbatim.
- Blocks: guaranteeing `role('secret')` never leaks across the settings wire.
- Priority: High.

**Session deletion / retention API:**
- Problem: no deletion or retention; logs and spill files accumulate unboundedly.
- Blocks: long-lived deployments and disk-bounded operation.
- Priority: Medium.

**Partial-turn resume:**
- Problem: crash repair always closes an interrupted turn with synthetic closers; there is no partial-turn resume that continues it.
- Files: `packages/session/session-persistence/README.md`
- Priority: Low (current behavior is safe, just lossy of the tail).

**Credential-scrub whitelist:**
- Problem: the scrub is a deny-list heuristic with a documented false-negative class (`*PASSPHRASE*` etc.); an over-scrub allow-list is noted future work.
- Priority: Medium.
